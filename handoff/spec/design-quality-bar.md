# 设计与体验质量线（sflipmloop 硬性基线）

这是本流程的**质量下限**，不是理想状态。规划案的所有决策都要落在这条线之上；
执行 Agent 收尾前要逐条对照自查，**每条都要有证据**。

> 判定原则：**看起来"差不多"= 不合格。** 下列每一条都能被眼睛看出来或被工具量出来。

---

## A. 视觉基础

### A1. 排版

- 字族必须**指定**（中文 + 西文 + fallback 完整栈），不许"用系统默认字体"。
- 字阶必须成体系：**比例固定**（推荐 1.2–1.25），层级不少于 6 级。
- 正文行长 **≤ 75 个西文字符 / ≤ 40 个中文字符**，超宽屏要限宽居中。
- 行高：正文 **1.5–1.75**，标题 **1.15–1.3**，紧凑控件 1.2–1.4。
- **不许**用浏览器默认的 `<h1>`–`<h6>` 字号（16/24/32px 那套）——必须重置。
- 数字、金额、代码用**等宽**或 `font-variant-numeric: tabular-nums`，不许随宽度跳动。
- 中西文混排要设 `font-feature-settings` / 标点挤压；正文**首行不缩进**、段间**用间距**不用空行。

### A2. 色彩

- 全部颜色来自**设计令牌**，代码里不许出现裸 hex（令牌文件除外）。
- 色板至少覆盖：背景 2–3 层、边框 2 层、文字 3–4 档、语义 4 色、强调 1–2 色。
- **对比度硬指标**：
  - 正文文字 vs 背景 **≥ 4.5:1**
  - 大字（≥18.66px 粗体 / ≥24px）**≥ 3:1**
  - 控件边框、图标 vs 相邻背景 **≥ 3:1**
  - 禁用态可以低，但**必须仍可辨认**（≥ 2:1）
- 不许只靠颜色传递信息（红绿状态必须配图标或文字）。
- 深色模式若提供：**两套色板独立定义**，不许把浅色色板机械反转。
- 焦点态颜色必须与选中态、悬停态**可区分**。

### A3. 间距与栅格

- **4px 基准栅格**；间距取值来自固定梯度（4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 96）。
- 同层级间距必须一致；**不同层级间距必须成比例**（越"重"的内容离边界越远）。
- 页面主容器必须**限宽并居中**（内容型 960–1200px，工具型可全宽但要定内边距）。
- 相关元素的间距 **<** 无关元素的间距（分组靠间距差，不靠框线堆砌）。

### A4. 形状与层级

- 圆角必须成体系（推荐 4 / 8 / 12 / 16 / 999），同类元素圆角一致。
- 阴影必须分档（0/1/2/3/4），每档对应明确层级（卡片/悬浮/下拉/模态/吐司）；
  **不许**出现"随手加的阴影"。
- z-index 必须集中管理并写成表，不许在组件里散落魔法数字。
- 分隔线用**边框或间距**二选一，不许同时用（线 + 阴影 + 底色三重复用是典型丑）。

### A5. 图标与媒体

- 图标来自**同一套图标库**（同一线宽、同一网格、同一端点风格），尺寸梯度统一。
- **禁止用 emoji 当正式界面图标**。
- 图片必须有 `alt`；装饰图 `alt=""`；图标按钮必须有 `aria-label`。
- 图片要定义宽高或 `aspect-ratio`，不许造成布局跳动（CLS）。
- 插画/占位图要有明确风格，不用灰色占位块敷衍。

## B. 交互与体验

### B1. 状态完整性（每个组件都要有）

| 状态 | 必须有 |
|---|---|
| 默认 | — |
| 悬停 | 可见变化，且**指针设备**才有（触屏不粘连） |
| 按下 | 比悬停更明显的反馈 |
| 聚焦 | **明显可见的焦点环**（≥2px 或 2px offset），键盘 Tab 顺序与视觉顺序一致 |
| 禁用 | 视觉降级 + **可被读屏识别**（`aria-disabled` 而非只 `disabled`） |
| 加载 | 有进度指示，不许界面无反馈地卡住 |
| 错误 | 就地提示 + 说明怎么修，不许只有红色边框 |
| 空 | **有引导**（这个状态该做什么），不许只写"暂无数据" |
| 成功 | 有确认反馈，操作结果明确可见 |

### B2. 反馈与时序

- 任何用户发起的操作，**100ms 内有反馈**（视觉或状态变化）。
- 异步操作必须有加载态；超过 **1s** 才有结果时要有进度说明，超过 **10s** 要能取消。
- 提交类操作要**防重复提交**（按钮禁用 / 幂等 / 队列）。
- 破坏性操作必须**二次确认**，确认弹窗要写清后果，不能只写"确定吗？"。
- 撤销优先于确认：可撤销的操作应提供撤销，而不是弹确认框。

### B3. 导航与信息架构

- 用户在任意页面都知道**自己在哪**（当前位置有标识）。
- 主要动作在首屏可见，不需要滚动就能完成核心任务。
- 返回/前进行为符合浏览器预期（不劫持）。
- 危险操作与主操作**不并排等权重**。
- 层级不超过 3 层；超过就要重组。

### B4. 文案

- 微文案写具体：说清**发生了什么、为什么、怎么办**。
- 按钮写动词短语（"保存更改"不是"确定"）。
- 错误文案**不出现技术黑话和堆栈**，给用户可执行的下一步。
- 不用"操作失败"这类无信息文案，必须说明失败原因类别。

### B5. 响应式

- 断点写死数值（常见 480 / 768 / 1024 / 1280 / 1440）。
- 每个断点都要有**明确的布局规则**（列数、留白、控件排列方式、导航形态），
  不许只写"自适应"。
- 移动端：可点区域 **≥ 44×44px**；表单控件不用 hover 才显示的操作。
- 不许出现横向滚动条（除刻意的表格/画布）。
- 图片与媒体按断点提供合适尺寸，不拉伸变形。

## C. 无障碍（底线要求，不是加分项）

- 键盘**可以完成全部核心操作**，Tab 顺序符合视觉顺序。
- 所有交互元素有**可见焦点**；焦点环不被 `overflow: hidden` 裁掉。
- 语义化标签：能用 `<button>` 不用 `<div onclick>`；标题层级不跳级。
- 表单：**每个控件有关联 label**，错误信息用 `aria-describedby` 关联。
- 图片有 `alt`；图标按钮有可读名称。
- 表单错误用 `aria-invalid` + `aria-errormessage`/`role="alert"`。
- 颜色不是唯一信息载体。
- 动效尊重 `prefers-reduced-motion`。
- 文字缩放到 200% 不丢失内容、不重叠。

---

## D. 性能

| 指标 | 目标 |
|---|---|
| 首屏可交互 | ≤ 2.5s（本地实测，不含网络抖动） |
| 交互响应 | ≤ 100ms 反馈，≤ 300ms 完成轻量操作 |
| 布局偏移 CLS | ≤ 0.1 |
| 字体/图片 | 字体 `font-display: swap` + 预加载关键字重；图片用合适格式与尺寸 |
| 动画 | **只用 `transform` / `opacity`** 做动画（避免触发 layout/paint）；能用 CSS 就别用 JS 循环 |
| 长列表 | 超过 ~200 项要分页或虚拟化 |

---

## E. 工程与一致性

- 设计令牌集中在**单一文件**，组件只引用令牌，不写字面量。
- 同类组件**视觉与交互完全一致**（圆角、阴影、间距、状态行为）。
- 不许出现"三处按钮长得不一样"。
- 组件库/样式有唯一真源；不重复造轮子，也不引一堆半吊子依赖。
- 命名、目录、文件职责一致；新增代码风格与既有代码一致。
- 无用代码、死代码、遗留 TODO 要清掉（不留在交付物里）。

---

## F. 交付前的自检方式

- **逐条对照**：A–E 每一条都有明确结论（通过 / 不适用 / 不通过）。
- **视觉检查**：在目标浏览器实际看过；至少看**默认态 + 空态 + 加载态 + 错误态 + 移动断点**。
- **键盘走查**：拔掉鼠标，只用 Tab / Enter / Esc 完成一遍核心流程。
- **对比度抽查**：正文、次要文字、边框、禁用态各抽查一处，确认达到 A2 的数值。
- **真实设备宽度**：至少在 375px 和 1440px 两个宽度下确认无破版。
- 上述结果写进执行报告，**不能只写"已检查"**——要写检查了什么、看到什么。

---

## G. 什么算"不合格"

以下任一出现，**即使功能全通也不算完成**：

- 页面还带着浏览器默认样式（默认按钮、默认字体、默认列表缩进）。
- 出现「暂无数据」「操作失败」「确定吗？」这类占位文案且没有更好的替代。
- 同类元素尺寸/圆角/间距不一致。
- 只有默认态做得好，悬停/聚焦/加载/错误/空态缺失或难看。
- 焦点看不见，键盘走不通。
- 移动端横向滚动、元素挤压重叠、按钮点不准。
- 用 emoji 或风格不一的多套图标。
- 颜色裸写、深浅色对比不足、只靠颜色表意。
- 动效掉帧、动画卡在 layout 属性上、或无视 `prefers-reduced-motion`。
