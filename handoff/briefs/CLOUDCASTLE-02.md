# 简报 CLOUDCASTLE-02：世界级「云上城堡」实时 Three.js 场景

## 任务

做一个**完整、实时、在浏览器里运行**的 Three.js 场景：**一座漂浮在云海之上的城堡**。

用户原话：「做一个完整的实时 Three.js 场景，城堡漂浮在云层之上……咱们这次的目标就是做个世界最精致的、最好的、效果最炫的云上城堡。」

不是 demo，不是教学样例，是**成品级的实时渲染作品**——打开的第一眼要像电影片头或作品集封面，经得起逐帧推看。

## 验收（可判定，一条命令或一个明确步骤就能判真假）

1. `npm ci && npm run build` 退出码 0；`npm test` 退出码 0。**测试条数从 `package.json#scripts.test` 的真实 stdout 读取，不许手抄。**
2. 真实 Chromium（Playwright 已装）打开**生产构建**（`vite preview`）：console 错误 0、未捕获异常 0、**外部网络请求 0**；落盘三张截图：1920×1080 主视角、1920×1080 侧视角、375×812 窄屏。
3. 性能（1920×1080，暖机后采 60 个**互不相同**的帧）：中位 FPS ≥ 55；draw calls ≤ 120；三角形 ≤ 1,500,000。
4. 画面判据（用脚本量，**不许肉眼估**）：
   - 主视角截图灰度直方图分桶 ≥ 200，且 99 分位与 1 分位亮度差 ≥ 0.55（不许整体压平成灰白）；
   - 主视角截图 HSV 饱和度中位数 ≥ 0.12（不许整体去色）；
   - 云层受光面与背光面（同一张截图内取两块 64×64 区域）归一化亮度差 ≥ 0.12。
5. 交互全部可用且有反馈：轨道旋转 / 缩放 / 平移、键盘复位、时间档位切换、画质档位切换、拍照模式隐藏 UI；`prefers-reduced-motion: reduce` 下不报错且动画减弱。

## 背景与约束

**本机**：macOS 26.4.1 arm64；Node v26.0.0；Python 3.9.6；无 TTY；无付费 API；可联网。
**依赖版本（已核实，就用这些）**：`three@0.186.1`、`vite@8.3.5`、`playwright@1.64.1`。

**本机已具备的能力 —— 务必用上，这是品质上限的关键：**

- **AI 文生图可用，本机已实测出图**：已用下列命令生成过一张 2048×2048 的城堡石墙 PBR 反照率贴图（分块砌缝、风化色带、苔痕），质量达可用标准。
  ```
  mcode-tools connector call connector__matrix__generate_image \
    --args '{"requests":[{"prompt":"<英文材质描述>","resolution":"2K","aspect_ratio":"1:1"}]}'
  ```
  返回 `success_items[].node_id`；取下载地址用 `mcode-tools get_asset_url <node_id>` → `download_url`，再 `curl -sL` 下载。
  可选值：`resolution` = `1K|2K|4K`；`aspect_ratio` = `1:1|16:9|9:16|4:3|3:4|21:9`；`input_urls` 可做图生图。
  一次调用约几秒到几十秒，可批量（`requests` 是数组）。
- **已实测的 PBR 贴图提示词经验**（照这个写，出图质量明显更高）：材质描述 + `seamless tileable texture` + `flat even lighting, no shadows, no objects` + `orthographic top-down` + `photorealistic PBR albedo map`。光照不均匀或带投影，会直接毁掉贴图的可平铺性与 PBR 用法。
- **零外部运行时依赖是硬要求**：不许用 CDN，不许引用任何外部模型 / 贴图 / HDR / 字体文件。**所有资产必须进仓库或运行时生成**，页面加载期间外部网络请求数必须为 0。
- **WebGL2 是安全基线**：无头浏览器里 WebGPU 支持不稳。规划 WebGPU 必须同时给出 WebGL2 回退分支。

**仓库现状**：全新空仓（只有 `handoff/`、`reports/`、`.gitignore`）。无既有代码、无既有约定，**架构由你从零定**。测试框架可用 `node:test` + Playwright（`node --test`）。

**本轮明确不做**：后端 / 账号 / 支付 / 多人；VR / WebXR；原生 App；音视频转码管线；真实天气 API。

## 调研：你必须自己去查。下面是我已核实的起点，不是终点

**要求：你必须自己去读这些来源，并在规划案里写清「从每个来源学到了什么」；同时继续自己扩展调研。**

1. **Halcyon** — https://halcyon.billpwchan.art ｜ https://github.com/billpwchan/halcyon
   浏览器内实时热带环礁，three.js + WebGL2，**零预渲染画面**，笔记本稳 60fps。公开了完整渲染管线：单次散射大气 + 半分辨率光线步进积云（带重投影）、三级 FFT 海面、半分辨率 GTAO、泛光、太阳光束、ACES 色调映射、LOD + impostor、**实时合成**的程序化音频、36 分钟昼夜循环、**帧时间调速器**（超预算就降渲染分辨率保帧率）。
   → 学：渲染通道的顺序与顺序依赖；体积云的「真」做法；帧率调速器这个保命的产品化手段；音效做成实时合成而不是音频文件。
2. **Above the Clouds（Burj Khalifa，Adrian Red）** — https://abovetheclouds.adrianred.com ｜ https://www.webgpu.com/showcase/burj-khalifa-gaussian-splatting/
   滚动驱动的 3D 概念站。**云海是真实体积雾**（Gaussian splatting），明确拒绝 billboard + noise 的糊弄做法；云海与建筑同帧合成；叙事锚点是「迪拜一年只有十来个早晨的雾季」。
   → 学：体积雾的合格标准；滚动 / 进度作为相机时间轴；用「一个稀有时刻」当整个作品的情绪钩子。
3. **Kage（Meng To）** — https://mengto.github.io/kage/ ｜ https://github.com/MengTo/kage
   单 HTML 文件、零构建、vendored three.js r149。五章节滚动夜游。**分层渲染**：实时 3D（程序化寺庙 / 灯笼 / 月亮 / 雾 / 雨 / 落叶）+ AI 生成的「场景画面层」静帧 + 带 alpha 的前景元素层 → 电影感。后处理克制（bloom + 胶片颗粒 + 暗角）。内建 `prefers-reduced-motion`。`PROMPT.md` 当设计规范发布。
   → 学：分层渲染怎么出电影感；克制后处理；零构建单文件分发形态；把设计规范写成可执行文档而不是口头描述。
   → 注意：Kage 的代码与美术作品**未授予复用 / 再分发许可**，只能学方法，不能搬资产。
4. **Sakura Fantasy（billpwchan）** — https://sakura.billpwchan.art ｜ https://github.com/billpwchan/sakura-fantasy
   three.js r186 + WebGL2，日式河谷四季实时切换，三级 LOD，**实时演奏**的程序化配乐（筝 / 尺八 / 笙），同样有帧时间调节器。
   → 学：程序化内容生成 + 分级细节；实时音画同步；季节 / 时刻切换的实现代价。
5. **WebGPU.com Showcase** — https://webgpu.com/showcase/
   实时 3D 作品的策展标准：怎么标注技术栈与制作流程、什么样的作品被认为「最炫」。
   → 学：什么样的作品能进这个展；元信息该标什么。
6. **Dan Greenheck 的 TIDEWATER** — Halcyon 自己公开设定的对标作品。
   → 学：先设定并公开一个明确的对标物。
7. **城堡建筑原型参考**（判断「什么才叫一座好看的城堡」，不要做成方盒子加圆锥顶）：
   新天鹅堡（Neuschwanstein）、圣米歇尔山（Mont-Saint-Michel）、阿尔罕布拉宫（Alhambra，庭院几何与镂空）、姬路城（白墙黑瓦、屋脊装饰）、爱丁堡城堡（岩基与城垛尺度感）、霍格沃茨原型（高耸塔楼群与垂直层次）。
   → 学：塔楼要有**高度层次与轮廓节奏**（主塔明显更高、附属塔递减）；墙面要有**水平分层线脚**打断大面积；屋顶要有**材质与檐口细节**；窗要有**深凹拱券**产生真实阴影；垂直方向要有**塔尖 / 旗杆 / 扶壁**等剪影元素。

查不到就如实写「未能查证」，**不许编造来源**。
